# alp-sdk-vscode Development Instructions

## SDK Submodule Policy (feat/alp-ide-hub branch)

**⚠️ IMPORTANT**: Do NOT update the `alp-sdk-upstream` submodule during this feature branch cycle.

- **Reason**: Feature branch focuses on alp-sdk-vscode tasks (wizard, CLI, packaging, extension bundling)
- **Current pinned commit**: `81c3683e85f03667b20b8ff41bc8701f9ba52c25` (origin/main as of 2026-05-15)
- **Impact of updating**: Unplanned changes to ALP SDK could break tests or introduce scope creep
- **Next update**: After feat/alp-ide-hub → main merge completes

**If SDK update becomes necessary**:
1. Contact team lead or create an issue
2. If forced update needed: `cd alp-sdk-upstream && git reset --hard origin/main` (loses local conflicts)
3. Re-commit: `git add alp-sdk-upstream && git commit -m "chore(submodule): ..."`

## Build & Packaging

- **Extension bundle**: `pnpm run bundle:ext` (esbuild into `out/extension.js` + `out/lsp/server.js`)
- **VSIX**: `pnpm run package` (uses `--no-dependencies` to skip npm ls devDep check)
- **CLI tgz**: `pnpm run cli:pack` (into `dist/alp-sdk-0.3.0.tgz`)
- **Both together**: `pnpm run compile && pnpm run package && pnpm run cli:pack`

## Testing

- **All tests**: `pnpm test` (136 pass, 4 skipped without bundle)
- **Wizard tests**: `node --test test/wizard.service.test.js`
- **CLI tests**: `node --test test/cli.*.test.js`
